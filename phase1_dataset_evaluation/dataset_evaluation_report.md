# Aerial House Detection — Public Dataset Evaluation (Verified Sources)

**Project:** Detecting individual houses from aerial/satellite top-view imagery → bounding boxes, confidence scores, total count per image. Detector: YOLO-family or DETR-family.
**Method:** All facts below were checked against official/primary sources (dataset homepages, official challenge terms, official GitHub repos, TorchGeo docs). Anything not confirmable from a primary source is marked **unverified**.
**Date of verification:** 2026-11-09

---

## 0. Important distinctions (as requested)

### FACTS — footprint/segmentation datasets vs. object-detection datasets
- **Object-detection (bbox) native datasets:** xView (GeoJSON bboxes), DOTA (oriented 4-point quads), AI-TOD (HBB+OBB), VisDrone/UAVDT (HBB). These train a YOLO/DETR detector directly.
- **Footprint/segmentation datasets:** SpaceNet (GeoJSON polygons), Inria (raster masks), Massachusetts Buildings (raster masks), WHU Building (raster masks + shapefile + a COCO-format polygon release), CrowdAI Mapping Challenge (COCO polygon segmentations), Open Cities AI (GeoJSON polygons). None label "house" as a semantic class — all label **"building"** generically.
- **"Building" class semantics:** None of the verified datasets distinguish houses from commercial/industrial structures. xView's 60-class ontology is the only one with *separate* building-related fine-grained classes ("Building", "Hut/Tent", "Shed", "Aircraft Hangar" per Ultralytics' published class list), which could let you exclude commercial classes. Everything else is one generic class; houses can only be separated implicitly (by size/shape heuristics or rural-imagery selection, e.g. Inria's Lienz/Kitsap tiles, WHU Christchurch, Open Cities informal settlements).

### FACTS — conversion burden to YOLO bboxes
| Annotation form | Conversion | Effort |
|---|---|---|
| COCO polygons (CrowdAI, WHU-COCO) | Take polygon extents → bbox; COCO→YOLO is a standard, well-documented step (many Roboflow/Ultralytics converters) | Trivial |
| GeoJSON polygons (SpaceNet, Open Cities, xView) | Rasterize/split GeoTIFF tiles, take polygon extents in pixel coords → bbox | Easy (scriptable; torchgeo already parses these) |
| Raster binary masks (Inria, Massachusetts, WHU raster) | Connected-component labeling per tile → per-instance bbox | Easy (e.g. cv2.connectedComponentsWithStats); tiny touching buildings merge |
| OBB quads (DOTA) | Take axis-aligned extent of the 4 vertices → HBB (Ultralytics' DOTAv1-yolo-hbb conversion exists) | Trivial |
| GeoJSON bbox (xView) | Direct GeoJSON→YOLO conversion (Ultralytics does it automatically on first training run) | None |

## 2. RANKING for this project (ASSESSMENT, built on the verified facts above)

1. **WHU Building Dataset (aerial, COCO-format release)** — *High.*
   Highest native resolution among the labeled sets (0.075 m native, 0.3 m tiles; a 0.2 m COCO release exists), 8,189 tiles with a clean official 4,736/1,036/2,416 split, single unambiguous "building" class that in Christchurch suburban imagery is overwhelmingly residential houses, and an official COCO polygon export → bbox conversion is trivial. ~5 GB is student-laptop scale. License on the official page is unstated (mirrors claim CC BY 4.0), so cite the paper and confirm terms — acceptable for research use.

2. **SpaceNet 1 (Rio) + SpaceNet 2 (Vegas/Paris/Shanghai/Khartoum)** — *High.*
   0.3–0.5 m WorldView imagery, >685k polygon footprints across the building datasets, clearly documented AWS download, and a **CC BY-SA 4.0** license stated on the official page — the cleanest license among the top candidates. Multi-city coverage is exactly what you want for a second/generalization dataset. Cost: GeoTIFF + GeoJSON handling and tile-splitting before YOLO.

3. **Inria Aerial Image Labeling** — *Medium-High.*
   0.3 m, 810 km², deliberately built for cross-city generalization (train cities ≠ test cities) — great as an evaluation benchmark for your counting model. Penalty: raster semantic masks (not instance labels), so bbox extraction needs connected components, and buildings merge when touching. License not stated on the official site (the popular CC BY-NC-SA claim is unverified) — fine for research, verify before any redistribution.

4. **xView** — *Medium.*
   The only verified dataset with house-adjacent *fine-grained classes* (Building / Hut-Tent / Shed) already in **bounding-box** form, 0.3 m, 1M+ boxes. But it's vehicle-dominated, requires registration, is CC BY-NC-SA 4.0 (non-commercial), and class imbalance means houses are a minor slice — best used to pretrain a backbone or to borrow its building/hut/shed subsets.

5. **Open Cities AI Challenge** — *Medium (as generalization set).*
   2–20 cm drone imagery, ~700–790k footprints, CC BY 4.0, and a completely different geography (African cities, many informal settlements) — ideal stress test for domain shift. Penalty: Radiant MLHub retirement makes the current download path unverified; quality of OSM-derived labels varies by region.

**Not recommended for houses:** DOTA (no building class), VisDrone/UAVDT (street-level drone, vehicles only), AI-TOD (no building class), Massachusetts (151 images, 1 m, one city — smoke-test only), CrowdAI Mapping Challenge (right format but ~90% duplicate images, 93% train↔val leakage per peer-reviewed analysis, and no working official download), Roboflow community roof sets (fine to garnish, too small/inconsistent to build on).

## 3. Recommended starting & generalization datasets (ASSESSMENT)

- **Starting dataset: WHU Building Dataset (aerial subset, COCO-format labels).**
  Why: highest resolution per label quality, official COCO annotations (one conversion step to YOLO), official splits, small download, suburban/individual-building character that matches "houses." Rank candidates by bbox mAP@50 and per-image house counts immediately.

- **Generalization / second dataset: SpaceNet 2 (multi-city, esp. Las Vegas + Khartoum) — optionally plus Inria test cities.**
  Why: SpaceNet 2 spans 4 cities on 3 continents under CC BY-SA 4.0 with polygon footprints → bbox; training on WHU (NZ aerial) and evaluating zero-shot on SpaceNet tiles measures cross-sensor + cross-continent robustness. Inria's disjoint-city design (train Austin/Chicago/Kitsap/Tyrol/Vienna, test Bellingham/SF/Innsbruck…) is an off-the-shelf generalization benchmark if you prefer segmentation-derived boxes.

## 4. Top pick — exact download route & conversion (WHU Building Dataset)

**Download route (FACTS):**
1. Go to the official page: `https://gpcv.whu.edu.cn/data/building_dataset.html` (Wuhan University GPCV, Dataset 1).
2. From the download list on that page, grab:
   - *"The cropped aerial image tiles and raster labels.zip (0.3 meter)"* (~5 GB) — 8,189 512×512 PNG tiles + raster masks, pre-split 4,736/1,036/2,416 (train/val/test); **or**
   - *"Dataset with labels in COCO format (0.2 meter)"* — the instance-level polygon/COCO release (preferred for bbox training); **or** the full aerial imagery + hand-edited shapefile (~25 GB) if you want to tile at native 0.075 m yourself.
   Alternative verified mirrors: Figshare `doi.org/10.6084/m9.figshare.25415098` (5.06 GB, CC BY 4.0) and Hugging Face `giswqs/WHU-Building-Dataset` (5.25 GB).

**Conversion steps (high level):**
1. **If using the COCO release:** parse each COCO annotation entry; for every polygon take min/max of its x/y points → axis-aligned bbox; normalize to YOLO format (`class cx/ w / h`, all relative to image W/H); write one `.txt` per image; single class "building" → YOLO class 0. (If you want "house" vs other buildings, filter instances by bbox area/pixel-size threshold on the Christchurch suburban tiles — a heuristic, flagged as ASSESSMENT.)
2. **If using the raster masks instead:** run connected-component labeling on each 512×512 mask; each component's pixel extents → bbox; drop components below a few pixels (noise).
3. Keep the official train/val/test split so results are comparable with published WHU benchmarks.
4. (Optional) For counting output: after YOLO inference, sum detections with confidence > threshold per image — no dataset work needed, but be aware adjacent connected houses merged in a single mask component will become one box; if per-house counts matter, prefer the COCO release where instances are separated.
